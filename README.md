# Smart Budget Shopping Assistant

## Project Overview
Smart Budget Shopping Assistant is a web-based prototype developed for Project Better Tomorrow using Pathway A – Continuation Track.

The application helps users plan purchases, manage a fixed shopping budget, distinguish needs from wants, explore price alternatives, and track savings goals.

## Problem Statement
How might we help customers shopping with a fixed budget make better purchasing decisions by tracking expenses and identifying budget-friendly alternatives?

## Key Features
- Shopping List: Add, edit, delete, search, filter, and sort shopping items.
- Budget Planner: Set and manage shopping budgets.
- Need vs Want Intelligence: Classify items and calculate category totals.
- Price Comparison: Display available comparison information for shopping items.
- Smart Recommendations: Provide rule-based suggestions.
- What-If Simulator: Explore alternative purchasing decisions.
- Spending Analytics: Summarize planned spending by category.
- Savings Goals: Track contributions and progress.
- Ask SmartBudget: Provide structured, rule-based shopping guidance.
- Prototype Validation: Record user feedback.
- Feedback & Iteration: Document improvements and retesting.
- AI Interaction Audit: Record AI assistance, decisions, and limitations.

## Technical Overview
The prototype uses React and TypeScript. Shopping data, budgets, and goals are stored locally in the browser using LocalStorage.

The current prototype does not require an external database or live retailer-price API.

## Input Validation and Error Boundaries
The application includes budget validation and displays a clear unavailable-data message when comparison prices are missing.

Additional boundary cases requiring systematic testing include negative amounts, invalid quantities, empty inputs, and browser storage restrictions.

## Known Limitations
- Retailer prices are not live.
- Price comparisons depend on available sample or entered data.
- Data is stored in the current browser rather than synchronized across devices.
- Recommendations are rule-based, not generated by a connected AI model.
- No external database or documented backend API is currently used.
